# Long-term memory: the options

Short-term memory (the daily file and `carry-forward.md`) is the same for everyone. Long-term memory has more than one good answer.

## Option A: `memory.md` (start here)

A file in your workspace with headings for standing rules, decisions, people, where things live and lessons. Every agent can read it; there is nothing to install.

- **Good for:** Levels 1 and 2, and the two-week trial.
- **Limits:** every session reads the whole file, so it gets slow and costly once it's long (a few hundred entries). Only agents with access to the folder can use it.

## Option B: a personal memory database

A small database with search by meaning, exposed to your agents as tools (for example over the Model Context Protocol): search, save, and load the standing rules at the start of a session. Several open-source projects do this; so does a table in any database you already run.

- **Good for:** several agents and devices sharing one memory, phones included, and memory that has outgrown a file.
- **Costs:** a database to run, keys to manage, and occasional upkeep.
- **Advice:**
  - Keep capture deliberate. Automatic import of email and tasks fills the memory with noise.
  - Give each agent its own key, so every write is attributed and can be audited.
  - Standing rules multiply until the full set no longer fits in a session and some contradict each other. Keep the owner's exact words, give each rule a scope, cap the number per scope, replace a rule rather than adding one that contradicts it, and prune rules that are never used.

## Option C: a shared knowledge base, for shared facts

Facts about your organisation (products, processes, policies) belong in whatever your team already shares and reviews, not in anyone's personal memory. Personal memory then holds only what's yours: your rules, your decisions, your people, your lessons.

## For a team

| Model | How it works | For | Against |
|---|---|---|---|
| **Private per person, plus a shared knowledge base** | Everyone has their own memory; shared facts go to the knowledge base | Private by default; uses a review process you already have | Learnings don't spread unless someone adds them |
| **One shared team memory** | Everyone's agents read and write one store | Simple; learnings spread at once | Personal and confidential notes mix; needs rules on who sees what |
| **Private, with a shared rules layer** | Private memories, plus one shared set of team rules every agent loads | Team rules apply everywhere; personal stays personal | Someone has to own the shared rules |

Start with the first. It needs no decision from anyone else.
